# 1. RESUME

**5G 3GPP Conformance Verification Pipeline — OpenAirInterface + offline RAG/LLM calibration**

- Built an automated **spec-to-evidence** pipeline that verifies a live 5G SA/NTN lab
  (OpenAirInterface gNB + nrUE + CN5G over RFsimulator) against 3GPP standards: each
  requirement becomes a machine-checkable contract, a Python/tshark verifier, and a
  saved PASS/FAIL evidence report with the governing TS clause.
- Implemented and validated **5 conformance checks** end-to-end — SUCI privacy
  (TS 33.501 §6.12), 5G-AKA RES*/XRES* (§6.1.3.2), initial registration (TS 24.501
  §5.5.1), PDU-session + user plane (§6.4.1), and multi-PLMN SIB1/MOCN order
  (TS 38.331 §6.3.1) — reproducing the network's Milenage/KDF offline to independently
  confirm authentication (recomputed RES* `98ffc4…` matched the network HXRES* exactly).
- Caught a **real privacy defect** the raw counts pass: a null-scheme SUCI carrying the
  IMSI in cleartext (`null_scheme_frames=2`), which a naive "is a SUCI present?" check
  would mark conformant. Also root-caused a 5G-AKA failure to a CU/DU PLMN-ordering
  divergence, and documented a post-handover user-plane blackhole (F1 HO RCA).
- Designed a **three-model calibration loop**: Claude as the spec-correct reference vs.
  two **offline models (llama3.1:8b, mistral) grounded in a local 3GPP-spec + failure-log
  RAG**. A diff tool flags every metric where the offline models deviate; corrections are
  recorded until all three agree, then the result freezes as a golden file. Surfaced that
  offline models get conformance *logic* right but hallucinate implementation detail
  (faked cryptography, invented enums, wrong protocol fields).
- Hardened with a human-owned pytest oracle and CI so verdicts can't silently regress.

### Article outline / draft

**Hook.** I wanted a checker that reads a 5G capture and tells me — with evidence — whether the
network followed the 3GPP rulebook. Not "looks fine": *this clause, this frame, PASS or FAIL.*
And I wanted the AI half to run **offline**, grounded in the actual specs. So I built it, pointed
a local model at it, and watched the model confidently invent a cryptographic function that
doesn't exist.

**1. The idea: the spec is the test.** For each feature, a human writes a `spec.md` contract
(MUST / MUST NOT + exact metrics + verdict logic). A Python verifier parses the pcap with tshark
and returns a verdict. The verdict is trusted because it survived a human-authored spec, a
reference implementation, and independent agreement — not because a model felt confident.

**2. The lab.** OpenAirInterface 5G SA (gNB + nrUE + CN5G) over the RFsimulator, including a
moving LEO NTN channel. A capture script freezes pcaps + logs by test case. Everything downstream
is pure analysis of that evidence — no live network needed.

**3. Five checks, one real defect.** SUCI, 5G-AKA, registration, PDU session, SIB1. Four pass.
SUCI **fails** — and that's the point: the capture contains a *null-scheme* SUCI, so the identity
decodes as "SUCI" (a naive check passes) but the IMSI is in cleartext. `null_scheme_frames = 2`.
The pipeline caught a real privacy hole that counting alone would miss. (Show the metrics + the
TS 33.501 §6.12 / Annex C reasoning. Note it's a lab-config gap — provision an ECIES key to fix.)

**4. Proving the crypto.** For AKA I didn't trust a log line saying "auth success" — I recomputed
RES* offline with Milenage + the TS 33.501 Annex A.4/A.5 KDF and matched it against the network's
HXRES* (`671faf…`). Bit-for-bit. That's what "verified" should mean.

**5. The offline brain: a 3GPP RAG.** The offline models (llama3.1:8b, mistral) are backed by a
local RAG — a FastAPI + Ollama service over an index of **3GPP specifications and real 5G failure
logs**. I used it to *generate* the offline verifiers, grounded in the retrieved TS clauses. Fully
offline, no cloud.

**6. Where it got interesting: the offline models are confidently wrong.** Given the same spec,
they got the conformance *logic* right almost every time — but botched the execution:
- llama3 **hallucinated the cryptography** — invented a `tshark -z crypto,hash,sha256` command
  instead of running Milenage.
- mistral was worse — it left the crypto as empty stub functions ("omitted for brevity"), invented
  a `VerificationResult.Verdict` enum, made up UDP-port filters, and even emitted a Python **syntax
  error** that wouldn't parse.
- Both used plausible-but-wrong tshark field names (`protection-scheme-id` vs the real `scheme_id`).

Same task, different failures per model — evidence the failure modes are model-specific, not a fluke.

**7. Calibration: turning wrong drafts into trustworthy checks.** A diff tool lines up all three
implementations metric-by-metric against the reference and flags every disagreement. I corrected the
offline impls until all three agreed — and logged every fix (`CALIBRATION_LOG.md`). The loop even
caught a subtle one: after the verdicts already matched, the diff flagged that the offline impls
emitted *fewer diagnostic metrics* than the reference — a divergence a verdict-only check would have
missed. When all three agree, the result freezes as a golden file.

**8. The takeaway.** A local, spec-grounded model is good enough to *draft* a conformance check but
not to be *trusted* with one — it will confidently fake the hard parts. The value isn't the model;
it's the scaffolding around it: a human-authored spec, a spec-correct reference, and a diff that
forces agreement. That's what turns an untrustworthy offline draft into a calibrated, trustworthy
verifier — and it's how I found an IMSI leak that a naive check calls conformant.
